# numgen 日期片段配置设计

## 背景

Issue #730 的实际阻塞点是编号管理页面无法可靠配置日期片段：页面没有 `MMdd` 预置项，自定义格式依赖下拉框的隐式创建行为，且预览示例不能反映自定义格式。后端还会把非法格式推迟到实际渲染时才暴露。

## 方案

- 保留现有 `dateFormat` 字段和 API 合同。
- 页面使用可见的文本输入作为日期格式主控，并提供常用格式快捷选择：`yyyy`、`yyyyMM`、`MMdd`、`yyyyMMdd`、`yyyyMMddHHmmss`。
- 页面本地校验格式语法，预览使用固定示例日期按 Java `DateTimeFormatter` 语义生成；后端校验作为最终权威。
- 后端保存/发布校验调用 `DateTimeFormatter.ofPattern`，将非法格式转换为明确错误。
- `sequenceScope=1` 的 DATE 片段继续作为流水分组键：使用 `MMdd`/`yyyyMMdd` 实现按日重置，使用 `yyyy` 实现按年重置。

## 测试

- 前端纯函数测试覆盖常用格式、`MMdd`、自定义格式示例和非法格式。
- 后端单元测试覆盖格式校验、渲染和分组键。
- 后端集成测试覆盖同日递增、跨日重置、同年递增和跨年重置。
- 运行 numgen 包构建、类型检查、前端单测及 Mango 后端定向 Maven 测试。
