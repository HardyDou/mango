## Business Impact

- Administrators gain a safer Notice channel edit path: secret material is masked by default and revealing one field requires explicit permission and produces an audit record. Existing manual plaintext is migrated lazily when the affected channel is saved, used, or explicitly revealed.
- WeCom-bound users receive provider nickname/avatar snapshots through Identity, and Notice delivery resolves WeCom recipients from the same binding source. Other providers and non-WeCom notification channels keep their existing behavior.
- Existing databases upgrade in place through Flyway. Identity V3 affects only `WECOM + SELF` bindings whose display name exactly equals the Mango nickname; V4 adds a nullable avatar file ID. A database backup and target-row count/sample are required before production rollout.
- Consumers must not mix Maven `1.0.38` with the previous frontend tuple. Direct frontend consumers must install every exact dependency version in this release; CLI-managed consumers use `@mango/cli@1.0.111`.
- No Mango application fat JAR, business application deployment, production configuration mutation, production database operation, or real WeCom call is performed by this artifact release.

## Upgrade Estimate

- Audience: Mango business applications using Auth/Identity, RBAC, Notice channel management, WeCom login or WeCom notification delivery; CLI-managed full frontend consumers.
- Engineering Effort: 1 to 2 hours for a standard generated consumer; 2 to 4 hours for direct/custom consumers that own dependency pins, permissions, Crypto configuration, or WeCom integration settings.
- Execution Window: 1 to 3 hours including backup, dependency upgrade, Flyway migration, focused API/UI verification, frontend production build, and an authorized WeCom smoke test when credentials are available.
- Service Downtime: no framework-mandated downtime; applications that do not run Flyway during rolling startup should reserve their normal database migration window.
- Rollback Effort: 30 to 90 minutes to restore the prior Maven/npm tuple and application build; restore the database backup only if business validation proves the bounded V3/V4 migration must be reversed.
- Assumptions: publish/consume registry access, a clean dependency lock, Mango Crypto configured for manual channel secrets, a database backup, and authorized WeCom application permissions/visibility/trusted IPs for provider-level acceptance.
