## Pull Requests

- [PR #915](https://github.com/HardyDou/mango/pull/915) Fixed cold Bootstrap when an `AUTH_MENU` declaration references a stable parent menu that is not ready yet. Packages: Mango Maven `1.0.47`, `io.mango:mango-docs-bundle:1.0.47` and generated `@mango/cli@1.2.7`. Business Adaptation: no configuration, permission or database migration is required; the incomplete module rolls back, independent modules continue and the deferred parent reference retries in the same Bootstrap coordination.

## Fixed

- Classify an unavailable external `AUTH_MENU.parentCode` as a retryable Resource dependency before manifest writes.
- Preserve same-manifest parent resolution and permanent rejection of a menu that points to itself.
- Prevent module, menu, frontend runtime configuration or successful receipt writes for a parent dependency that has not converged.

## Changed

- Lock generated consumers to Mango Maven `1.0.47` through `@mango/cli@1.2.7`; all existing frontend and PMO package versions remain unchanged.

## Versions

- Mango Maven non-application reactor and `io.mango:mango-docs-bundle`: `1.0.46` to `1.0.47` (192 coordinates).
- `@mango/cli`: `1.2.6` to `1.2.7`; its compatibility matrix advances Mango Maven to `1.0.47` while retaining PMO `1.4.4` and the existing npm tuple.

## Published Packages

1. Publish the 192-coordinate Mango Maven `--all-non-app` and docs bundle batch at `1.0.47`; application and capability-app fat JARs remain excluded.
2. Publish generated `@mango/cli@1.2.7` after Maven/docs `1.0.47` is visible from both registry roles.
3. Create the Tag and GitHub Release only after dual-registry and clean pure-consumer verification.

## Business Impact

- Empty-database consumers whose Authorization manifest encounters a cross-module parent menu before its provider module can complete Bootstrap in the first formal startup instead of requiring a second application start.
- Missing parent dependencies roll back the current module, remain retryable and do not block unrelated Resource modules in the same pass.
- Same-manifest menu trees continue resolving by stable `menuCode`; self-parent declarations remain permanent failures.
- No database migration, public API change, new permission, administrator fallback or module hard-order dependency is introduced. This release does not deploy a business application or mutate production data.

## Upgrade Estimate

- Audience: Mango generated applications and direct Resource/Authorization Bootstrap consumers.
- Engineering Effort: 30 to 60 minutes for generated consumers; up to 2 hours for direct integrations with custom cross-module menu declarations.
- Execution Window: 1 to 2 hours including dependency upgrade, clean build and first-start empty-database verification.
- Service Downtime: no framework-mandated downtime; consumers use their normal application restart window.
- Rollback Effort: 15 to 30 minutes to restore Maven `1.0.46` and CLI `1.2.6`.
- Assumptions: Java 21, Node `22.23.1`, configured registries and an isolated empty database where the referenced parent menu is declared by a later Resource module.
