## Pull Requests

- [PR #1042](https://github.com/HardyDou/mango/pull/1042) Fixed file uploads that failed below the multipart threshold because the request Content-Type stayed application/json. Packages: @mango/file@1.1.4, @mango/common@2.1.4 and generated npm dependents through @mango/cli@1.2.20. Business Adaptation: upgrade the npm tuple and remove the explicit multipart workaround in business upload helpers.

## Fixed

- Files below the multipart threshold (default 20 MiB) upload again: @mango/file upload, uploadBatch and uploadServerPart, and the @mango/common instance upload helpers, now declare multipart/form-data so the host JSON default header no longer serializes FormData into JSON.

## Business Impact

- Affected consumers: business frontends that consume @mango/file, @mango/common and the dependent admin packages through the published npm tuple.
- No API, data, database, menu, permission, tenant or configuration change. Maven and docs stay on 1.0.58; this batch is npm-only.
- Consumers that added an explicit multipart Content-Type workaround can remove it after upgrading.

## Upgrade Estimate

- Audience: teams consuming @mango/file and @mango/common from the Mango npm registry.
- Engineering Effort: low; replace the npm tuple and rebuild.
- Execution Window: one deployment window; no database work.
- Service Downtime: none for the npm-only release.
- Rollback Effort: low; restore the previous npm tuple.
- Assumptions: consumers resolve @mango packages from the Mango registry and do not pin workspace links.

## Upgrade Notes

- Upgrade @mango/file to 1.1.4 and @mango/common to 2.1.4 together with the generated dependents through @mango/cli@1.2.20.
- Remove the explicit multipart Content-Type workaround from business upload helpers (for example uploadPdfForCompression.ts) and verify small-file uploads through the normal file API.

## Verification

- Unit and contract tests: pnpm --filter @mango/file test and pnpm --filter @mango/common test.
- Builds: pnpm --filter @mango/file build and pnpm --filter @mango/common build.
- Real link: upload a file below the multipart threshold through the file management page and assert the request Content-Type is multipart/form-data and the response is HTTP 200.

## Rollback

- Roll back by restoring the previous versions @mango/file@1.1.3 and @mango/common@2.1.3 plus the previous dependent tuple, and keep the uploaded file records; no data rollback is required.
- Published npm coordinates are immutable; rollback uses a consumer-side version pin, never a republish.
