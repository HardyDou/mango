# 交付契约与设计说明规则

## 1. 适用范围

本文件只定义交付契约、轻量设计说明和交付台账被用户选作执行载体时如何编写、检查和复用。它们不是固定措施目录之外的额外默认措施，也不因“正式任务”、风险等级、PR 或发布自动创建。

- 用户启用 M05 TDD 时，优先使用 TDD；只有用户明确要求轻量设计载体时才使用本文的设计说明格式。
- 用户启用 M06 实施计划且需要原子交付追踪时，可把交付台账作为实施计划的执行视图。
- 用户未启用相关文档或计划措施时，可以在会话、PR body 或忽略的运行时状态记录目标、范围和确认基线，不得强制新增版本控制文档。
- 发布由独立发布流程处理，不以本文作为发布授权或发布恢复门禁。

## 2. 目标

防止 Agent 将任务压缩成极简主链路、聚合页、演示页、临时实现或不可用交付。

## 3. 开工门禁

用户确认采用交付契约作为已启用措施的执行载体后，开始对应工作前必须明确契约内容。

交付契约必须说明：

- 目标
- 范围
- 不做什么
- 设计输入
- 交付物
- 验收方式
- 测试用例登记与自动化判断
- E2E 覆盖判断
- 测试结果基线
- 业务开发交接输出
- 风险与限制

## 4. 设计说明门禁

只有用户确认 M05=`ENABLE` 或明确选择轻量设计说明作为执行载体时，才进入本节门禁。

- 已有设计文档时，设计说明必须引用该文档并抽取原子要求。
- 没有设计文档且用户没有启用 M05 时，不自动生成轻量设计说明；实现边界可记录在确认基线或会话中。
- 设计说明必须写清模块边界、接口变化、数据变化、菜单/页面/权限变化、测试范围。
- 对外能力新增、修改、删除或重构时，设计说明必须写清 README、需求文档、设计文档、E2E 脚本和测试结果基线是否需要同步更新。
- 未经用户确认，禁止把完整任务改成 MVP、第一阶段、纵向切片或演示版本。

## 5. 交付台账门禁

只有用户确认 M06=`ENABLE` 并选择交付台账作为实施计划执行视图，或用户明确要求台账时，才必须建立交付台账。

交付契约只登记用户已启用措施对应的测试或人工验收项，明确其优先级、数据、执行入口、证据和状态；不得为了填表重新启用 M08-M16。

交付台账必须从用户要求、设计说明、设计文档和验收标准中抽取原子验收项，逐项记录：

- `ID`
- `来源`
- `要求`
- `设计决策`
- `代码交付物`
- `README/使用说明`
- `需求/设计文档`
- `E2E 脚本`
- `测试结果基线`
- `验收方式`
- `状态`
- `证据文件`

推荐使用模板：

```text
mango-pmo/templates/delivery-contract.md
```

## 6. 原子验收项规则

- 一个后台能力、业务能力、接口能力、数据能力、菜单能力、页面能力、权限能力或验收标准必须是一条独立台账项。
- 多个能力禁止合并成一个“管理页”“概览页”“主流程”“通用能力”台账项。
- 要求涉及菜单、页面、API、数据、权限、E2E 时，台账项必须逐类列出代码交付物、README 或使用说明、需求或设计文档、E2E 脚本、测试结果基线和验收证据。
- 只有 M08、M09-M16 中对应措施已启用时，台账才要求相应 README、脚本、结果或人工证据；未启用项记录确认值即可，不作为 `EXCEPTION`。
- 无法落地的项必须标记为 `EXCEPTION`，并记录用户确认依据。

## 7. 禁止替代

未经用户明确确认，禁止用以下内容替代交付契约：

- 用聚合页替代多个独立管理页面。
- 用 MVP、第一阶段、纵向切片替代完整范围。
- 用主链路跑通替代完整后台、接口、数据和验收能力。
- 用前端临时菜单替代后端入库菜单。
- 用 Mock、虚拟、演示数据替代要求的沙箱或真实能力。
- 用单元测试、接口 200、页面打开或口头说明替代应有的 E2E 脚本和测试结果基线。
- 用“后续优化”“未来补齐”替代本次明确要求。

## 8. 验证门禁

启用并采用本文资产时，交付前必须执行：

```bash
node mango-pmo/tools/delivery-contract-check.mjs \
  --design <设计说明或设计文档路径> \
  --ledger <交付台账路径> \
  --mode verify
```

验证模式下：

- 设计说明或设计文档必须存在。
- 台账必须存在。
- 必填列必须完整。
- 必需交付项必须存在。
- 只有确认基线中的对应文档、能力说明和验证措施均启用时才追加 `--require-materials`；检查器不得自行补加措施。
- 状态必须为 `DONE` 或 `EXCEPTION`。
- `EXCEPTION` 必须有证据文件或用户确认说明。
- 交付范围内不得存在 `TODO`、`FIXME`、`mock`、`virtual`、`模拟`、`伪代码`、`未来优化`、`后续优化` 等未交付标记。

## 9. 交付报告

采用交付台账时，最终交付必须报告：

- 交付台账路径。
- 台账总项数。
- `DONE` 项数。
- `EXCEPTION` 项数。
- E2E 脚本路径或 EXCEPTION 依据。
- 测试结果基线路径或 EXCEPTION 依据。
- 未完成项。
- 台账检查命令与结果。
- 新增、修改、废弃的测试用例清单。
- 面向业务开发者的测试用例、执行入口、数据边界、失败处理和升级动作。

未完成项不为 0 时，禁止声明“完成”。
