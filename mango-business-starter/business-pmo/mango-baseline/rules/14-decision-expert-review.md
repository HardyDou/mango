# 决策专家意见与同行评审规范

## 1. 适用范围

- 适用于 Agent 对范围、需求、文档内容、Issue 处理、技术方案、代码实现、测试结论、交付状态、PR、发布或治理规则作出的决定。
- 机械性格式调整、拼写修正、已经由当前规则唯一确定且不改变含义的执行，不视为本规则中的决定。
- 本规则不能替代需求审批、技术设计审批、QA 验收、PR Review 或发布授权；它要求在这些动作之前形成可复核的决定依据。

## 2. 三轮独立意见

每个需要决定的事项必须组织至少三轮相关专家意见。三轮应分别覆盖不同视角，并先独立给出意见，再合并结果：

1. **事实与用户视角**：目标、场景、读者/用户、当前事实、范围和成功/失败边界。
2. **技术与风险视角**：模块边界、接口、数据、权限、租户、兼容性、恢复方式和风险。
3. **验证与交付视角**：可观察结果、测试证据、文档/Issue/PR 影响、责任人和后续动作。

每轮意见至少记录：

- 负责视角和参与者；
- 使用的当前来源；
- 结论、依据和不确定项；
- 反对意见或未解决冲突；
- 对下一轮的输入。

不能访问真实子 Agent 或专家时，可以先执行标明“角色视角分析”的隔离模拟，但不得把模拟结果称为真实专家、人工理解或审批结果。

## 3. 方案整理与同行评审

三轮意见完成后，Agent 必须整理一份最终方案，至少包含：

- 决定和不决定的事项；
- 采用方案及选择依据；
- 被拒绝的替代方案及原因；
- 影响范围、剩余风险和回退方式；
- 验证命令、验收标准和证据位置；
- 需要人工确认的事项、责任人和截止时间。

最终方案必须再经过同行评审。同行评审至少检查：事实是否准确、范围是否越界、风险是否遗漏、验证是否能证明结论、文本是否清晰。评审必须记录阻断问题、非阻断建议和结论。

## 4. 状态与权限

- 三轮意见未完成：`ASK` 或 `WRITE`，不得进入最终决定。
- 存在未解决阻断意见：`BLOCKED`，不得标记 `PASS` 或 `NEXT`。
- 三轮意见和同行评审完成，但需要业务、技术、QA、实施负责人或发布人的正式审批：保留对应审批状态，不得由 Agent 代签。
- 治理、发布、权限、租户、数据破坏和不可逆变更必须保留真实人工责任人；角色模拟不能关闭该门禁。
- 低风险的机械执行可以直接按当前唯一规则执行，但必须在输出中明确“依据当前规则执行”，不伪造专家意见。

## 5. 禁止事项

- 禁止只给一个未经比较的方案并称为最终决定。
- 禁止让同一个未经独立思考的意见重复充当三轮专家意见。
- 禁止把 Agent 自评、空白 Agent、历史聊天或模型生成内容冒充真实专家或人工同行评审。
- 禁止在方案整理后跳过同行评审直接修改规则、发布、关闭 Issue、通过验收或标记 `NEXT`。
- 禁止用“大家同意”“风险可控”“测试通过”等无责任人、无证据的句子替代评审记录。
