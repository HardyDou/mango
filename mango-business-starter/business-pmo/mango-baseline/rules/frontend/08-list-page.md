# 列表页 UI 规范

## 1. 页面结构

1. 列表页内容区不展示页面标题、面包屑、页签标题。
2. 列表页不展示“搜索条件”“数据列表”等卡片标题。
3. 标准结构为：搜索区、功能区、表格区、分页区。
4. 搜索区和表格区通过白底、轻阴影、圆角和间距区分。
5. 新增列表页必须优先使用 `@mango/common` 的 `MangoListPage`、`MangoSearchPanel`、`MangoListPanel` 和 `Pagination` 组织骨架。
6. 禁止在业务页面自定义 `.operation-page`、`.query-form`、`.table-toolbar`、`.pagination-wrap` 等替代统一骨架的页面结构。

## 2. 搜索区

1. 搜索条件使用 `MangoSearchPanel` 承载，业务只声明 `el-form-item` 字段，不在页面内重写搜索区布局。
2. 桌面端搜索项使用稳定字段宽度，不因为只有 1 个筛选项就横向铺满整行；移动端可以单列撑满。
3. 搜索项多于默认展示范围时必须启用 `collapsible`，收起态只显示常用搜索项。
4. 常用搜索项按字段顺序表达，业务把高频条件放在前面；需要精确控制时使用 `collapsed-count`。
5. 展开态显示全部搜索项，展开/收起按钮跟随查询、重置按钮区域。
6. 查询、重置、展开或收起按钮统一位于搜索卡片右下角；展开前后位置必须稳定。
7. 主按钮顺序固定为查询、重置、展开或收起。
8. 展开/收起图标使用 Element Plus Icons。
9. 时间范围使用 range 类型，不拆成两个无关联输入。
10. 搜索条件变化后分页回到第一页。

## 3. 功能区

1. 功能区通过 `MangoListPanel` 的 `actions` slot 放业务操作。
2. 不默认放刷新、列设置、密度切换等工具按钮；确需视图操作时放 `view-actions` slot。
3. 功能区按钮统一使用 `plain` 风格。
4. 主操作使用 `primary plain`。
5. 危险操作使用 `danger plain`。
6. 批量操作未选择数据时禁用。
7. 删除类按钮即使禁用，也保留 `danger` 语义。

## 4. 表格区

1. 表格使用 `ElTable` 或项目统一表格组件。
2. 表格列宽、状态、操作列和分页保持稳定。
3. 操作列固定右侧。
4. 行内操作使用文本按钮。
5. 行内删除使用 `danger` 文本样式。
6. 空值统一显示 `-`。
7. 状态统一使用 `ElTag` 或公共状态组件。
8. 分页位于表格下方，分页数据由接口结果驱动。

## 5. 检查清单

1. 是否误放页面标题、面包屑或卡片标题。
2. 是否使用 `MangoListPage`、`MangoSearchPanel`、`MangoListPanel` 和 `Pagination`。
3. 搜索项较多时是否按常用项在前并启用展开/收起。
4. 查询、重置、展开或收起按钮是否在搜索卡片右下角且展开前后稳定。
5. 单筛选项是否保持合理宽度，未横向铺满整行。
6. 功能区按钮是否统一 `plain`。
7. 删除、批量删除是否使用 `danger`。
8. 表格操作列、状态列、分页是否稳定。
9. 是否覆盖 loading、empty、error 和无权限状态。
