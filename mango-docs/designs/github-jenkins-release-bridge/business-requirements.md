# GitHub 与内网发布协同业务需求说明书

## 1. 业务背景与问题

| 问题ID | 当前现状 | 业务问题 | 影响对象 | 影响程度 | 事实来源 |
|---|---|---|---|---|---|
| BP-001 | 代码评审在 GitHub 完成，Maven 成品只能进入内网仓库，发布动作依赖人工切换到内网操作 | 发布等待时间长，公开评审记录与内网发布结果不能自动对应，失败后需要人工查找执行批次 | Mango 维护者和业务项目开发者 | L3；错误批次可能造成平台版本与消费版本不一致 | 2026-07-14 GitHub、内网 Jenkins 和发布历史盘点 |

## 2. 业务目标与成功口径

| 目标ID | 来源问题ID | 目标对象 | 当前基线 | 目标值或完成条件 | 统计周期 | 统计口径 |
|---|---|---|---|---|---|---|
| BG-001 | BP-001 | Mango Maven 发布 | 人工在 GitHub 与内网发布平台间重复操作 | 从 GitHub 手工发起后，内网按同一提交和版本执行，结果自动回到原发布记录；默认只试运行 | 每次发布 | GitHub 执行号、提交摘要、版本和内网构建号一一对应 |

## 3. 范围与不处理范围

| 范围ID | 范围类型 | 业务能力或场景 | 适用对象 | 边界说明 | 对目标的影响 |
|---|---|---|---|---|---|
| BS-001 | 纳入范围 | GitHub 手工发布、内网执行、状态回传、失败停止和重复请求控制 | Mango 发布负责人 | 只覆盖 Maven 非应用部署物料，默认试运行，正式发布必须基于主分支已批准版本 | 直接支撑 BG-001 |
| BS-002 | 不处理范围 | 公共代码评审任务进入内网、Nexus 暴露公网、自动创建版本说明和自动合并代码 | 外部贡献者和其它发布类型 | 公共评审继续使用 GitHub 计算资源；npm、文档站和业务部署另行治理 | 防止扩大内网攻击面和发布范围 |

| BA-001 | Mango 发布负责人 | 确认主分支版本、发布说明和验证结果，并手工发起发布 | Maven 试运行和正式发布 | 选择版本、试运行和是否执行测试，查看内网结果 | 从非主分支正式发布、绕过版本锁和重复发布不可变版本 | 保证公开变更记录与内网成品可追溯 |
