# ADR：前端代码规范采用边界

## 状态

已接受。

## 背景

Mango 前端规范需要证明规则、工具、模板和业务消费方式能够落地，但规范本身不是一个承接用户流量的业务应用。此前执行记录把规范毕业与业务应用发布混在一起，错误地要求 5% / 25% 生产流量灰度和真实故障注入。

## 决定

前端规范使用以下状态：

- `STANDARD_VALIDATED_LOCAL`：固定工具链、Mango 自身代码、候选 tarball 和封闭业务消费者验证通过。
- `STANDARD_READY_FOR_ADOPTION`：远端 CI 门禁、使用说明和至少一个真实业务试点验证通过，可以扩大采用范围。
- `STANDARD_ENFORCED`：目标仓库已经启用强制门禁，新增和修改代码受新规范阻断，存量债务只减不增。

采用过程按对象推进，不按用户流量推进：

1. `pilot`：CMS 和业务生成模板执行严格规则。
2. `affected`：所有本次变更影响的 workspace 和独立消费者执行规则。
3. `repository`：全仓启用新增代码严格阻断与存量精确棘轮。

npm 包仍保留精确候选版本、上一稳定版本和 `pin/remove` 回退矩阵，用于证明业务项目可以恢复依赖；它不代表真实部署环境已经执行回退。

具体业务应用的生产流量灰度、监控观察、故障注入和生产回滚继续由独立发布流程负责，不进入前端代码规范完成定义。

## 结果

### 正面

- 代码规范的完成条件可以由仓库和独立消费者直接验证。
- 不再用模拟流量数据冒充生产发布证据。
- npm 包兼容性与具体业务部署职责保持清晰。

### 代价

- 规范达到 `STANDARD_ENFORCED` 不能证明任一业务系统已经发布生产。
- 业务应用发布仍需单独维护部署、监控和回滚证据。

## 备选方案

1. 保留 0% / 5% / 25% / 100% 流量门禁：拒绝，因为规范不是生产流量承载对象。
2. 完全删除采用和回退检查：拒绝，因为无法证明规则能被业务项目渐进接入，也无法证明包版本可恢复。
3. 使用仓库/业务包采用阶段并保留精确依赖回退矩阵：采用，证明对象与验证手段一致。

## 非功能要求

- 可重复：固定 Node、pnpm、容器镜像和精确 lockfile。
- 可追溯：报告绑定完整 Git commit、Git tree 和 tarball SHA-256。
- 可隔离：业务消费者不读取 Mango workspace 源码，封闭阶段禁止网络访问。
- 可维护：新增代码严格阻断，历史债务使用精确 identity 棘轮。
- 安全：报告不得包含 token、密码或私有仓库凭据。
