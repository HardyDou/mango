# Mango 业务项目 CI/CD 指南设计

## 1. 背景与目标

Mango 已提供业务项目脚手架、PMO 基线、Maven/npm 发布物料和多种部署拓扑，但尚缺一份面向业务项目的完整 CI/CD 接入说明。不同项目容易分别决定版本、镜像 Tag、环境晋级、回滚和清理方式，后续难以共享工具和运维经验。

本次新增一份业务无关的实践指南，给出 Mango 业务项目可以直接采用的默认发布模型。它同时是推荐实践和新项目默认基线，但不新增 PMO 强制门禁，项目可以根据基础设施和发布责任调整。

## 2. 范围

本次包含：

- 构建、测试发布、生产发布三个独立 Pipeline 的职责边界。
- 应用版本、候选构建号、镜像 Tag、Git Tag、Release 和 digest 的关系。
- 多应用选择、并行构建、Docker Compose 部署、健康检查和回滚。
- Harbor 制品组织、保留策略以及 Jenkins 磁盘维护建议。
- 凭据边界、权限拆分、最低验收证据和偏离项记录方式。
- 业务接入场景索引和 Mango 能力地图入口。

本次不包含：

- 可直接安装的 Jenkins Job、共享库、Business Starter 模板或 Harbor 自动配置。
- 对现有 Pipeline、发布脚本、Maven/npm 发布流程和运行环境的修改。
- 任何具体业务名称、仓库、域名、IP、端口、应用名称、凭据或现有 Job 名称。
- 新增长期强制规则或 CI Required Check。

## 3. 方案比较

| 方案 | 做法 | 优点 | 代价 |
|------|------|------|------|
| 单一业务接入指南 | 用一份场景指南串起完整发布链路，并加入能力地图 | 入口集中，业务项目容易照着落地；不重复 PMO 规则 | 文档较长，需要清晰分节 |
| 拆分多份专题指南 | 分成构建、制品、部署和运维四份文档 | 单篇边界小，适合多人维护 | 首次接入需要来回跳转，容易出现重复口径 |
| 直接生成流水线模板 | 在 Business Starter 中提供 Jenkins、Harbor 和 Compose 模板 | 自动化程度高 | 过早绑定基础设施，实现和验证范围显著扩大 |

采用“单一业务接入指南”。模板化作为后续独立能力评估，本次只提供可落地的默认模型和参数建议。

## 4. 文档设计

指南归档到：

```text
mango-docs/guides/business-integration/ci-cd-release-practices.md
```

入口同步到：

- `mango-docs/guides/business-integration/README.md`
- `mango-docs/capabilities/README.md`

指南按以下顺序组织：

1. 定位、适用范围和非强制边界。
2. 默认工具组合与三段式发布模型。
3. 版本、Tag、digest 和发布清单。
4. 构建、测试发布、生产发布的数据流。
5. Docker Compose 部署、健康检查和回滚。
6. Harbor 制品保留、Jenkins 构建缓存和磁盘维护。
7. 权限、凭据、审计证据和偏离项登记。

## 5. 核心决定

- 默认采用“一次构建，多环境晋级”，测试和生产使用同一镜像 digest。
- 默认把构建、测试发布和生产发布拆成三个独立、可参数化的任务。
- 默认从仓库内 `VERSION` 读取应用发布线，候选构建号使用北京时间 `yyMMddHHmm`。
- 默认以 `biz-<project>/<app>` 组织业务镜像，部署清单记录每个应用的版本、Git SHA 和 digest。
- 默认使用 Docker Compose 在目标服务器按 digest 拉取镜像；镜像和 JAR 不通过文件复制发布。
- 默认允许多应用按需选择，未选择应用保留当前 digest。
- 默认保留生产制品，按时间清理候选和测试制品；基础镜像、代理缓存和基础设施项目单独治理。
- 默认保留有价值的 BuildKit 依赖缓存，通过上限和磁盘余量做回收，不采用每天清空缓存的方式。

所有决定都以“推荐默认值”进入指南，不成为 PMO 强制条款。

## 6. 验证范围

本次只改变文档和索引，验证聚焦以下静态事实：

- 新指南可从业务接入手册和能力地图进入。
- Markdown 相对链接可以解析。
- 指南明确非强制边界，没有把推荐值写成 PMO 规则。
- 全文不包含任何具体业务标识、内网地址、凭据或现有 Job 名称。
- 能力说明和文档源事实检查通过。

运行时、API、数据库、UI、Maven/npm 制品和部署环境均不发生变化，因此不执行运行态测试或发布验证。
