# Mango 信息采集中心系统需求规格说明书

> **先读：这份文档要回答什么**
> - **一句话目标：** 系统让授权人员管理表单，让访客通过托管入口或业务自建入口提交信息，并让运营人员处理当前表单的提交记录。
> - **真实场景：** 管理员从表单管理进入某个表单，配置采集项后启用；访客提交信息；运营人员从该表单详情进入提交记录列表，查看动态采集项列并处理记录。
> - **关键输入 / 输出：** 输入包括表单属性、采集项定义、访客提交值、来源页面和处理动作；输出包括表单状态、提交记录、动态列表列、处理状态和失败反馈。
> - **成功与失败：** 成功入口使用同一份启用定义并形成真实记录；失败时不形成半条记录，租户边界、状态和字段校验失败均有明确反馈。
> - **明确不做：** 不提供独立提交记录菜单，不做工作流、营销自动化、复杂条件编排、支付、签名和首版文件上传；文件上传仅保留为 P1 设计预留。
> - **阅读顺序：** 先看系统边界和参与者，再看功能、交互和页面，最后看数据、非功能、验收和追踪矩阵。
