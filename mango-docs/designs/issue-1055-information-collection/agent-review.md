## 3. 修改后的产品基线

### 3.1 菜单和页面

后台只保留一个菜单：`信息采集 / 表单管理`。

后台管理页面：

1. **表单列表**：查询、新增和表单级操作。
2. **表单详情**：元数据、采集项定义、接入方式入口。
3. **表单配置**：表单属性、控件选择、采集项属性、预览和保存。
4. **当前表单提交记录**：关键字/状态筛选、动态列、导出、详情抽屉和处理结果。

托管表单是公开入口，不作为后台菜单；自建入口复用同一份启用表单定义和校验规则。提交记录必须从当前表单上下文进入，不提供全局提交记录菜单。

### 3.2 表单列表和操作

固定列：表单名称、表单编码、备注、状态、提交量、创建日期、更新日期、创建人、操作。

操作：新增、详情、配置、接入、提交记录、启用/停用、删除。

删除规则：无提交记录时允许删除；已有提交记录时只能停用。停用保留历史记录并拒绝新提交。

### 3.3 提交记录动态列

列表列顺序固定为：

1. 前置固定系统列：记录ID、提交时间、状态、来源页面；
2. 中间动态列：当前表单采集项；
3. 末尾固定操作列。

历史提交保留提交时的字段编码、字段名称和取值快照，不能因当前表单修改而错列。处理状态为待处理、处理中、已完成、已关闭；已关闭记录不能继续处理。

### 3.4 接入与安全

- 托管入口和浏览器公开提交不使用 SK。
- 服务端提交使用当前表单专属 SK。
- SK 只允许服务端保管；浏览器源码、网络响应和托管页面不得出现 SK。
- 后台接入方式区域持续显示当前表单 SK，支持复制和重新生成；重新生成后旧 SK 失效。
- 服务端确定租户归属，客户端不能提交或覆盖租户归属。
- 失败提交不形成成功记录；停用、缺失、格式错误、超限、非法归属或反滥用拒绝均返回可识别失败原因。

### 3.5 首版范围

首版包括：文本、数字、手机号、邮箱、单选、多选、下拉、日期、说明文字、分割线；表单配置、托管提交、自建入口提交、提交列表、动态列、详情、处理状态、备注和导出。

文件上传为 P1，不作为基础采集闭环的研发阻断项；不做工作流、自动分派、营销自动化、复杂条件编排、支付、签名和多步骤表单。
