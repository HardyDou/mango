# 信息采集 功能介绍

> 本文面向业务方，用于确认功能是否满足需求。技术细节见 `system-requirements.md`、`technical-design.md`。

## 1. 这是什么

平台内置的**表单收集与处理**能力：业务人员自己拖拽出表单，发给用户填写（或让第三方系统直接调接口提交），提交结果统一在后台查看、处理和导出。

**不需要开发写页面，也不需要建站点**——它独立于内容运营（CMS），只负责「把数据收上来、管起来」。

## 2. 能解决什么问题

| 场景 | 做法 |
| --- | --- |
| 官网/活动收集线索 | 拖出「姓名 + 手机号 + 需求描述」表单，把生成的链接挂到官网或海报 |
| 内部报名、调研、反馈 | 表单加「城市、咨询类型、评分」等控件，设置必填，发链接给指定人群 |
| 第三方系统回传数据 | 对方服务端按接口文档提交，用当前表单的专属密钥鉴权 |
| 长表单（一次填多条明细） | 用「子表单」「表格表单」控件，一条记录里录入多行明细 |

## 3. 核心能力

| 能力 | 说明 |
| --- | --- |
| 表单设计 | 复用平台成熟设计器（与工作流表单同源），拖拽式搭表单，实时预览 |
| 控件支持 | 文本、多行文本、密码、数字、单选、多选、下拉、开关、评分、滑块、日期/时间、颜色、上传、富文本、子表单、表格表单、级联、树形选择等 |
| 校验规则 | 必填、类型校验、字段白名单：绕过页面直接调接口的请求同样会被拦截 |
| 两种接入方式 | ①页面接入（免登录直接填）②接口接入（服务端调用，需专属密钥） |
| 采集记录 | 独立菜单入口，按表单筛选，列随表单字段动态变化，行操作「处理」 |
| 处理流转 | 待处理 / 处理中 / 已完成 / 已关闭，支持处理备注、快捷处理 |
| 数据导出 | 按当前筛选条件导出 CSV，字段按原值输出，便于回访 |
| 附件上传 | 上传控件与富文本里的图片/文件统一存入平台文件模块，可在文件中台管理 |
| 安全与隔离 | 表单专属密钥可一键轮换；数据按租户隔离；停用表单立即不可提交 |
| 幂等提交 | 接口可带幂等键，重复提交不会产生重复记录 |
| 代码化内置 | 业务模块可在代码里声明内置表单，随服务启动自动同步，无需人工录入 |

## 4. 两种接入方式

### 方式 ① 页面接入（无需密钥）

把地址发给访客，打开即可填写提交，**不需要登录**。后台接入页提供：

- **页面地址**：可直接复制分享
- **页面效果**：模拟浏览器窗口内实时预览
- **页面嵌入**：一段 iframe 代码，可直接贴进已有业务页面（如官网、活动页）

```
https://<域名>/#/information/hosted?formCode=客户联系表
```

### 方式 ② 接口接入（需要表单专属密钥）

第三方或自有系统在**服务端**调用，用当前表单的专属密钥鉴权；密钥只放服务端环境变量，不会下发到浏览器。后台接入页直接给出 5 种语言的示例代码，复制即可用：

- cURL
- Postman（可直接导入）
- Java（JDK 11+ 内置 HttpClient）
- JavaScript（Node 服务端）
- Python（requests）

```
POST /information/open/forms/submit
Content-Type: application/json

{
  "formCode": "customer-contact",
  "serverSecret": "<当前表单专属 SK>",
  "values": { "name": "...", "phone": "...", "need": "..." },
  "idempotencyKey": "外部业务单号（可选，用于防重复）"
}
```

> SK 走**请求体字段 `serverSecret`**，不是请求头；表单编码也在请求体里，不在 URL 路径上。

> 示例里的字段名和表单实际字段一一对应，不用手工对照。

## 5. 采集记录与处理

- **独立菜单**：`信息采集 → 采集记录`，不依赖某张表单
- **筛选**：表单 / 关键字（姓名、手机号、内容）/ 处理状态 / 提交时间范围，筛选条件写入地址栏，可刷新、可分享
- **列表**：记录 ID（雪花主键）、提交时间、状态、来源页面 + 当前表单的采集项列（列随表单变化）
- **处理**：点行操作「处理」打开右侧抽屉，查看完整内容、填写处理备注、更新处理状态
- **导出**：导出当前筛选结果，字段按原始值输出
- **展示友好**：多选、子表单、表格表单等复杂内容自动转成可读文本（如「项目: 服务费，数量: 2」），不会出现乱码

## 6. 权限与安全

| 项 | 说明 |
| --- | --- |
| 公开入口 | 只有「已启用」表单可被匿名访问，停用后立即不可提交 |
| 密钥 | 表单专属，后台始终可见（默认打码，可点「显示」），可一键重新生成，旧密钥立即失效 |
| 租户隔离 | 表单与采集记录按租户隔离，跨租户不可见 |
| 附件 | 上传前需领取短效票据（10 分钟），票据与表单绑定，不能跨表单复用 |
| 记录可见性 | 采集记录仅对拥有该菜单权限的角色开放 |

## 7. 开发/运维用：代码内置表单（Resource 预置）

除了在后台手工建表，业务模块还可以**随代码声明内置表单**，服务启动时自动同步到系统，适合「能力随模块一起交付、不想人工建表」的团队。

- 已实现并实测通过：声明 → 启动同步 → 生成表单（含专属密钥）→ 匿名打开 → 提交成功
- 重复同步只更新表单定义，**不会产生重复表单**，也**不会重置专属密钥**（不影响已接入的调用方）
- 声明非法（缺必填、定义格式不对、没有可提交字段）会同步失败，不会放出坏表单
- 新增 `disable` / `delete` 支持停用与删除
- 声明格式、字段说明、覆盖语义见模块 README 第 6 节

> 提示：内置表单以其声明为准，后台手改的字段会在下次同步时被覆盖。**需要业务长期人工维护的表单，建议用后台新建，不要用资源声明。**

## 8. 本版本边界（暂不支持，需业务确认是否必要）

1. **公开提交暂不做防刷限制**（验证码、频率限制、大小/类型限制目前是可开关的配置，默认关闭）
2. **不做 iframe 之外的更深嵌入协议**（如 SDK 组件级嵌入、登录态透传）
3. **不做表单数据的分发/通知**（提交后不自动发短信、邮件、企微通知）
4. **不做数据看板/统计图表**（只有列表、筛选、导出）
5. **不做审批流**（只有「待处理/处理中/已完成/已关闭」四态人工流转）
6. **不做字段级权限**（有菜单权限即可看到全部字段，按原值展示，不脱敏）

| # | 待确认问题 | 我们的默认选择 |

| 1 | 公开表单是否需要防刷（验证码 / 频率限制 / 附件大小与类型限制）？ | 首版关闭，需要时可打开 |
| 2 | 提交后是否需要自动通知（短信/邮件/企微/站内信）？ | 不做 |
