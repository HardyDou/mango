# Issue #588 质量基线跨 Worktree 交付记录

## 1. 元数据

- 任务 ID：ISSUE-588-QUALITY-BASELINE
- 交付模式：FULL（修改平台 Java 质量门禁自身，影响所有 Mango 与业务消费项目的 PR 判定）
- 需求影响：L3 - 历史质量债务被误判为新增会阻断业务升级和主仓 PR。
- 方案风险：L3 - 改变质量报告指纹持久化和基线匹配语义，错误匹配可能放行真实新增问题。
- 最终风险：L3
- 工作区决策：CREATE（`fix/issue-588-quality-baseline`）
- 适用措施：M01、M08、M09、M10、M14、M15。
- 非降级事实：平台质量门禁修改自身。

## 2. 目标与范围

- Issue：[HardyDou/mango#588](https://github.com/HardyDou/mango/issues/588)。
- 改前事实：`gate=all` 报告没有指纹；加载另一个业务 worktree 产生的无指纹基线时，路径归一化依赖 Mango 固定目录锚点，任意业务根目录保留绝对路径并误判为新增。
- 目标：所有 gate 模式持久化基于生成项目根的稳定指纹；加载基线优先消费持久化指纹；同一业务项目不同绝对 worktree 根路径、行号漂移时仍匹配同一历史问题。
- 不处理范围：不修改质量规则、问题描述、严重级别、`changedOnly` 信任边界、正式历史债务预算或业务仓临时基线。

## 3. 可观察系统要求

| ID | 场景 | 前置条件 | 预期行为 | 失败语义 | 验收标准 |
|---|---|---|---|---|---|
| SR-001 | 生成 `gate=all` 报告 | 扫描发现历史问题 | `issues` 及引用同一对象的分类列表包含稳定指纹 | 指纹为空使后续基线不可移植 | 指纹使用项目相对路径且不包含行号 |
| SR-002 | 跨业务 worktree 比较 | 基线和当前扫描位于不同绝对根，业务目录为 `baohan-backend` | 加载器优先使用基线内持久化指纹 | 不得依赖 `mango-platform` 等固定锚点 | 同一问题进入 `baselineIssues`，`newIssues=0` |
| SR-003 | 真实新增问题 | 文件、规则或稳定描述身份变化 | 不匹配历史指纹并继续阻断 | 不得因宽松后缀匹配放行 | 既有负例和重复计数测试继续通过 |
| SR-004 | 旧版报告 | 基线由旧插件生成且没有指纹，或包含行号敏感旧指纹 | 无指纹及可识别的旧指纹回退到现有稳定兼容计算 | 无法可靠推断任意旧绝对根时不得猜测 | 同根、既有 Mango 锚点和旧行号指纹兼容测试不回归；文档要求跨 worktree 前重建基线 |

## 4. 技术决定

| ID | 对应要求 | 决定 | 理由 | 回滚方式 |
|---|---|---|---|---|
| TD-001 | SR-001 | `finalizeResult` 在 gate 分流前为正式问题和排除问题统一写入 `stableFingerprint` | 保证 `all` 与 `no-new-violations` 报告契约一致，分类列表引用同一问题对象 | 恢复仅在 no-new 分支写指纹 |
| TD-002 | SR-002/SR-004 | `loadBaselineFingerprints` 调用 `fingerprintForBaseline`，优先使用新稳定指纹；无指纹或可识别的行号敏感旧指纹回退到稳定兼容计算 | 生成时拥有正确项目根；新报告不再用当前 worktree 根重解释路径，旧 no-new 报告也不会在升级后整体失效 | 恢复始终重新计算基线指纹 |
| TD-003 | SR-003 | 保持基于完整稳定 identity 的计数消费，不增加任意路径后缀或文件名匹配 | 防止一个历史问题豁免多个新增问题或跨目录误匹配 | 无数据回滚 |

## 7. 发布与兼容

- 修复需要随下一版 Mango Maven 插件发布；业务项目必须使用该版本重新生成一次可跨 worktree 复用的基线。
- 旧报告没有记录生成项目根，也没有持久化指纹；框架继续支持可确定的既有兼容场景，但不会通过模糊路径猜测扩大豁免范围。
- 无数据库、HTTP、菜单、权限、租户或前端变化。

## 8. 剩余风险

- 基线仍按稳定 identity 和出现次数匹配；同一文件同一规则产生完全相同稳定描述的重复问题依靠计数区分，既有重复计数测试继续作为防回归门禁。
