任务：富文本托管图片与附件

## 1. 元数据

- 任务 ID：rich-text-managed-assets
- 交付模式：STANDARD
- 需求影响：L2 - 改变公共富文本组件的默认上传、持久化和回显行为，并新增附件节点协议
- 方案风险：L2 - 涉及共享组件、异步上传、WangEditor 插入链路和持久化 HTML 兼容，但不改变后端接口或数据库结构
- 最终风险：L2
- 工作区决策：CREATE - `codex/rich-text-managed-assets`

## 2. 目标与范围

- 目标：让 `@mango/common` 的富文本组件通过工具栏、复制粘贴和拖拽统一上传图片与附件；编辑态使用实时地址，持久化只保存文件 ID token，并提供只读回显能力。
- 成功条件：组件上传的图片和附件保存为 `mango-file:<id>`；图片立即可见，附件显示文件名并在新标签优先预览；重新编辑和只读预览会按 ID 查询最新地址；用户自带的 Base64、Blob、签名地址、第三方图片和普通链接保持原样。
- 处理范围：公共 Editor、托管 HTML 转换、文件上传结果规范化、公共只读富文本组件、组件示例、能力说明、业务排障指南无影响记录、单元测试、包构建和浏览器交互验证。
- 不处理范围：后端文件接口、数据库、文件删除与孤儿文件清理、业务发布、npm 升版、公开站点匿名文件鉴权策略。

## 8. 例外与剩余风险

- 当前不改变匿名公开站点的文件鉴权；公共预览组件允许由公开站点注入自己的 resolver。
- 上传后用户删除节点产生的未绑定文件仍按文件中心既有生命周期处理，本任务不新增清理接口。
- 隔离数据库、后端和管理端已启动并通过健康检查，但受保护页面缺少可复用自动化登录态，未形成图片/附件真实网络上传的自动化证据；上传请求、返回地址规范化和插入结果由单元测试中的 API mock 验证，仍需在消费环境保留文件中心联调回归。
- 管理端受保护组件路由被现有登录 Mock 缺少机构接口阻塞，页面验证改用 Git 忽略目录中的独立本地验证页；未修改登录逻辑。`admin-shell` 全量 `vue-tsc` 也受现有工作区模块解析和大量历史类型错误阻塞，公共包自身构建成功。
