# Issue #1010 前端质量门禁第一阶段决策复核

> **先读：** 第一阶段恢复真实 PR 检查；非构建质量问题只记录建议，受影响前端构建失败才阻断 PR。

## 1. 决定摘要

- **决定：** PR 使用 `pnpm check:pr` 执行真实检查；仅受影响 workspace 的递归生产构建失败阻断，其它检查失败记录为 advisory 并继续执行。
- **不决定：** 不清理存量 ESLint 诊断，不更新静态质量基线，不恢复 PR 全量零债务阻断，不改变 main push/manual 深度门禁。
- **读者下一步：** 在任务 worktree 执行同源 PR 检查；合并后回读真实 PR check-run 和 advisory evidence。
- **依据来源：** `.github/workflows/frontend-quality.yml`、`mango-ui/scripts/quality/check-affected.mjs`、`mango-ui/scripts/quality/quality-command-plan-lib.mjs`、Issue #1010。
- **状态：** REVIEWED

## 2. 第一轮：事实与用户视角

| 参与者/角色    | 当前事实                                                                 | 用户场景与成功/失败边界                                                      | 不确定项                                        | 意见                                   |
| -------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------------- |
| Agent 事实视角 | PR job 当前只输出暂停 notice；Issue #1010 记录主分支已有 ESLint identity | 用户需要 PR 仍能看到质量结果，但不应被无关存量问题阻断；真实构建失败必须可见 | 真实 GitHub PR 的执行时间和 advisory 数量待回读 | 恢复真实检查比继续空成功更符合用户目标 |

## 5. 方案整理

| 项目       | 内容                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| 采用方案   | 恢复 PR workflow，使用 `check:pr`；非构建失败转 advisory；递归 workspace build 失败阻断                           |
| 选择依据   | 满足“第一阶段只建议、系统无法产出可运行前端时阻断”的用户要求，并保留现有主干深度检查                              |
| 被拒绝方案 | 继续空跑 PR job：没有质量证据；全部恢复阻断：会重现 Issue #1010 的存量误阻断；直接更新 baseline：掩盖基线归因问题 |
| 未解决冲突 | 静态基线和存量债务仍需独立治理；真实 PR 运行时间和远端 required check 结果待回读                                  |
| 影响范围   | PR 前端 workflow、PR affected check 编排、质量策略单测和治理记录                                                  |
| 剩余风险   | 类型、测试、架构、包契约失败在第一阶段可能进入 PR；main/manual 深度入口继续暴露这些问题                           |
| 评审选择   | AGENT_ONLY                                                                                                        |
| 人工确认   | 未请求外部同行评审；用户已明确第一阶段阻断策略                                                                    |
