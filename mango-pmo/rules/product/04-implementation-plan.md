# L5 实施与验证计划规范

本规范只用于 `L5` 实施计划。`L2-L4` 的实施内容写入对应单文档。新文档使用 `mango-pmo/templates/l5-implementation-plan.md`，并由 `mango-pmo/tools/check-lean-document.mjs` 检查。

## PLAN-001 交付物与任务

- 交付物使用 `DEL-xxx`，写明目标路径/模块、完成状态和验收来源。
- 任务使用 `TASK-xxx -> TD-xxx`，写到文件、配置或符号级动作；一个任务只承担一个清晰目标。
- 引用本次采用的编码/测试规范和代码模板，写精确版本或 commit/SHA。
- 任务不得新增需求或设计；设计不完整时停止并返回技术设计。

## PLAN-002 顺序与依赖

- 写清前置任务、可并行条件、外部依赖、责任角色和失败停止条件。
- 契约、数据结构或事件未稳定时，不安排依赖它们的并行实现。
- 发布、制品、版本、tag 和发布恢复转独立发布流程。

## PLAN-003 验证

- 验证使用 `VAL-xxx -> TASK-xxx` 或 `VAL-xxx -> SR-xxx`。
- 每项写命令或步骤、环境/数据、观察对象、明确断言、证据位置和失败处理。
- 不用“补测试”“充分回归”“启动成功”等无法证明业务结果的表述。

## PLAN-004 数据、切换与回滚

- 数据或切换步骤写前置检查、执行顺序、校验、停止条件、补偿/回滚和责任角色。
- 不可逆数据动作必须取得明确授权；未知环境、账号、租户或数据事实可集中询问。
- 兼容路径必须有范围、退出条件和清理任务，不保留无期限双轨。

## PLAN-005 移交边界

实施负责人确认任务、依赖和验证可执行，Tech Lead 确认计划未改变设计。Agent 不把未执行计划写成完成结果。
