# 交付等级与文档治理规范

## 1. 核心规则

- 需求影响和方案风险分别评估，最终等级取两者较高值。
- `L0/L1` 不创建交付文档；`L2/L3/L4` 各使用一个文档；`L5` 使用四个独立文档。
- 文档只写当前任务适用内容；禁止用“不涉及前端”“无数据库变化”等条目填充不适用章节。
- 产品和技术内容必须引用实际采用的规范、代码示例或当前源码，并记录精确版本或提交。
- 直接追踪关系固定为 `US -> BR`、`SR -> US/BR`、`TD -> SR`、`TASK -> TD`，`VAL -> SR/TASK`；全量矩阵、摘要、审批和 checker 结果由工具维护。
- 发布、版本、制品、tag、Release 和发布恢复继续使用独立发布流程。

## 2. 工作区策略

1. 只读操作使用 `NO_WORKTREE`。
2. 同一任务已有非 main worktree 时使用 `REUSE`。
3. 主工作区发生受版本控制文件变更时自动使用 `CREATE`，在仓库外创建同级 worktree。
4. 只有用户明确要求并确认风险时使用 `MAIN_EXCEPTION`。
5. 同一任务不得创建第二个 worktree。

## 3. 等级与文档

| 等级 | 适用事实 | 文档 |
|---|---|---|
| `L0` | 不改变业务结果、系统行为或公共契约 | 无 |
| `L1` | 单点、可逆、单模块局部行为，边界明确 | 无 |
| `L2` | 已有功能的小改动，影响可限定且容易回滚 | `templates/delivery-l2.md`，不超过 1 张 A4 等效内容 |
| `L3` | 完整功能、多角色、多用户故事或多模块协作，恢复方式明确 | `templates/delivery-l3.md`，不超过 3 张 A4 等效内容 |
| `L4` | 跨模块/服务，涉及公共契约、数据、安全、租户、事务、并发或兼容 | `templates/delivery-l4.md`，不超过 5 张 A4 等效内容 |
| `L5` | 新模块、新系统、重大架构替换、核心系统迁移、不可逆数据处理或跨系统主链路 | 业务需求、系统需求、技术设计、实施计划四个独立文档 |

新模块或新系统固定使用 `L5`，不得因首期范围小而降级。行数、文件数和实现简单不能降低已经成立的影响等级。

## 4. 单文件要求

### L2

只包含：目标与范围、用户故事、系统满足方式、参考规范与代码、技术改动、验证与风险。

### L3

只包含：业务与用户故事、系统满足方式、名称术语与适用图、参考规范与代码、技术设计与变更字典、实施验证。

### L4

沿用 L3 主线，只增加实际适用的系统边界、API/事件、数据迁移、权限租户、事务并发、兼容切换和分阶段实施内容。

## 5. L5 文档

1. `templates/l5-business-requirements.md`：背景、公司/管理者/系统用户诉求、范围、编号用户故事、业务规则、验收和参考依据。
2. `templates/l5-system-requirements.md`：统一系统/模块/功能名称和简称、业务术语，逐项说明 `BR/US` 如何被 `SR` 满足，并提供适用的流程图、状态图或数据流图。
3. `templates/l5-technical-design.md`：逐项说明 `TD` 如何支撑 `SR`，记录规范、代码基线、实现设计、完整或变更字典、兼容回滚和测试设计。
4. `templates/l5-implementation-plan.md`：引用采用的规范和代码模板，把 `TD` 拆成文件或符号级 `TASK`，记录依赖、完成标准、`VAL`、迁移、失败停止和回滚。

## 6. 名称、图和字典

- 没有实际使用简称时不创造简称；存在简称时必须唯一且无冲突。
- 多步骤协作使用流程图；有生命周期使用状态图；跨系统数据交换使用数据流图。只画适用图，图中名称和状态必须与正文一致。
- `L2-L4` 只记录新增或修改的枚举、状态、字段、错误码、权限、配置、事件和外部代码映射。
- `L5` 新模块或新系统在技术设计中建立完整公共字典；已有且未修改的字典只引用代码源。

## 7. 询问边界

以下事实无法从用户输入、批准上游、规范或仓库事实确定时，Skill 必须集中询问，禁止自行补写：

- 业务目标、角色诉求、范围和成功结果；
- 用户故事的前置条件、允许/禁止行为和失败结果；
- 系统责任边界、名称、状态、数据语义和外部责任；
- 会改变公共契约、数据、安全、租户、兼容或回滚的关键技术选择；
- 请求降低默认等级、执行破坏性数据库动作或进行外部写操作。

等价实现细节、可从现有规范和代码直接确认的事实、验证重试不询问。

## 8. 验证能力

M09-M16 只按真实观察面启用。风险等级不自动增加无关测试；无 UI 的 L4/L5 不启用 UI 验证。每个验证必须说明观察对象、断言、入口和失败处理。

## 9. 禁止事项

- 禁止 `L0/L1` 生成交付文档。
- 禁止 L2-L4 拆成多份阶段文档。
- 禁止 L5 把四份内容重新塞进一个大文档。
- 禁止复制规范正文、批量列出未采用参考资料或手写全量追踪矩阵。
- 禁止使用“相关改造”“充分测试”“保持兼容”“后续优化”代替具体对象、断言或边界。
