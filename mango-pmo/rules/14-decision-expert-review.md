# 决策复核与可选同行评审规范

## 1. 适用范围

- 适用于 Agent 对范围、需求、文档内容、Issue 处理、技术方案、代码实现、测试结论、交付状态、PR、发布或治理规则作出的决定。
- 机械性格式调整、拼写修正、已经由当前规则唯一确定且不改变含义的执行，不视为本规则中的决定。
- 本规则要求形成可复核的决定依据，但不默认强制外部专家或人工同行评审；已有需求、验收、发布或审批合同另有要求时，继续遵循对应合同。

## 2. 三视角复核与评审选择

每个需要决定的事项先由 Agent 组织三类视角的事实分析，并先询问、再记录是否需要外部同行评审：

1. **事实与用户视角**：目标、场景、读者/用户、当前事实、范围和成功/失败边界。
2. **技术与风险视角**：模块边界、接口、数据、权限、租户、兼容性、恢复方式和风险。
3. **验证与交付视角**：可观察结果、测试证据、文档/Issue/PR 影响、责任人和后续动作。

每个视角至少记录：

- 视角名称和分析参与者；
- 使用的当前来源；
- 结论、依据和不确定项；
- 反对意见或未解决冲突；
- 对下一步的输入。

评审选择必须记录为以下之一：

- `AGENT_ONLY`：用户确认只保留三视角 Agent 分析，不发起外部同行评审。该记录不称为人工评审或人工审批。
- `EXTERNAL_PEER_REVIEW`：用户要求外部同行评审，记录评审人、范围、阻断问题、建议、结论和后续动作。

询问没有即时答复时，可以记录“未指定，按 `AGENT_ONLY` 继续”，并保留再次发起外部评审的入口；不得因未邀请人工评审而自动阻塞任务。

不能访问真实专家时，可以执行标明“Agent 角色视角分析”的隔离分析，但不得把分析结果称为真实专家、人工理解或审批结果。

## 3. 方案整理与可选同行评审

三视角分析完成后，Agent 必须整理最终方案，至少包含：

- 决定和不决定的事项；
- 采用方案及选择依据；
- 被拒绝的替代方案及原因；
- 影响范围、剩余风险和回退方式；
- 验证命令、验收标准和证据位置；
- 评审选择、询问记录和需要人工确认的事项、责任人和截止时间。

用户选择 `EXTERNAL_PEER_REVIEW` 时，按记录的范围组织评审；用户选择 `AGENT_ONLY` 时，记录 Agent 分析结论即可。两种选择都必须记录阻断问题、非阻断建议和结论，但不把 Agent 结论写成同行评审结论。

## 4. 状态与权限

- 事实、范围或关键决定未确定：`ASK` 或 `WRITE`；这不等同于等待人工同行评审。
- 存在未解决阻断意见：`BLOCKED`，不得标记 `PASS` 或 `NEXT`。
- 用户选择外部评审但未完成时，按用户记录的前置条件处理；本规则不自动把外部评审升级为合入门禁。
- 需要业务、技术、QA、实施负责人或发布人的正式审批时，保留对应审批状态，不由 Agent 代签；本规则不新增审批人，也不删除其它合同已有的审批要求。
- `AGENT_ONLY` 只能表示 Agent 分析已记录，不表示真实人工评审、人工理解或正式审批已完成。

## 5. 禁止事项

- 禁止只给一个未经比较的方案并称为最终决定。
- 禁止把 Agent 自评、空白 Agent、历史聊天或模型生成内容冒充真实专家、人工同行评审或人工审批。
- 禁止省略评审选择和询问记录。
- 禁止用户选择外部评审后伪造评审人、结论或审批证据。
- 禁止用“大家同意”“风险可控”“测试通过”等无责任人、无证据的句子替代复核记录。
