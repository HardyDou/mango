# 标准交付记录

> **写作与决定门禁：** 遵循 [`Agent 文本输出规范`](../rules/13-agent-text-output.md)。先写结论、影响和下一步，明确事实、失败语义与证据。交付决定另按 [`决策复核规范`](../rules/14-decision-expert-review.md)记录三视角分析、方案整理，并询问、记录是否需要外部同行评审。

## 0. 使用合同与最小填写方式

填写人是本次交付的 Dev/QA 负责人；事实来源是需求、设计、命令输出、测试报告和人工验收证据。STANDARD 记录的下游使用方是 Review、发布负责人和复盘人员。

| 区域 | 用途 | 填写人/事实来源 | 下游用途/使用方 | 校验方式 |
|---|---|---|---|---|
| 元数据 | 标识任务、风险和 worktree 决策 | 交付负责人；任务与 PMO 记录 | 选择门禁和审计 | STANDARD checker |
| 可观察系统要求 | 把目标写成可验证输入、行为、失败语义和验收标准 | Dev/QA；BRD/SRS/TDD | Review、测试和验收 | 必须至少有一行 |
| 技术决定 | 记录接口、数据、权限、兼容性和回滚 | Tech Lead/Dev；TDD | 实施和 Review | 每个决定有影响路径 |
| 实施清单 | 记录改动路径和完成条件 | Dev；Plan 和 git diff | Review、发布 | 每项可回读 |
| 验收映射 | 关联要求、命令、结果和证据 | QA；测试输出 | 发布和复盘 | 每个要求都有验证或明确例外 |
| 例外与风险 | 保留未完成项、限制和下一步 | Owner/Approver | 发布决策 | 不得用 `None` 隐藏未关闭风险 |

**最小合格示例（复制后替换，不要保留示例）：**

- 要求：给定已登录且有权限的用户，重复提交同一业务号返回同一结果；越权请求返回禁止反馈。
- 决定：使用业务号唯一索引和服务层幂等校验；回滚为移除新路由并保留数据。
- 验收：执行 `npm test -- order`，结果 `PASS`，证据为测试报告路径。
