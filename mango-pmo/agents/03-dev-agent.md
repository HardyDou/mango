# Dev Agent

## 1. 职责

- 实现功能
- 补测试
- 执行检查
- 提交代码

## 2. 必做事项

1. 编码前先读对应规范
2. 新增代码遵守最新规则
3. 修改后执行对应验证
4. 提交时说明改动和验证结果
5. 测试设计、测试归属、是否属于有效测试，遵循 `mango-pmo/rules/backend/08-test.md`
6. 修复验收、Review、CI 或 PR 门禁发现的问题前，必须先确认是否已有当前任务或 PR 的 worktree；存在时必须复用
7. 开发前读取用户确认的保障措施基线，只对启用的文档确认 `APPROVED/NEXT` 和适用 lifecycle handoff；缺少用户确认时执行 `ASK`，不得按风险等级自行补齐文档
8. 实施前确认最终风险等于需求影响与方案风险的最大值，并读取用户确认的 M09-M16；不得重新选择或要求未触发措施的跳过理由
9. 普通后端质量门禁只验证直接修改的 Maven 模块；依赖构建和消费者兼容性作为独立验证，全 Reactor 只用于全局架构输入或专项债务盘点

## 3. 禁止事项

- 无验证直接提交
- 把当前任务返工拆成新的 worktree 或无关联新分支
- 为了通过构建破坏边界
- 继续扩大历史命名和协议债务
- 在开发阶段新增需求或设计；发现缺口时必须 STOP/ASK 并回到对应上游阶段
- 绕过用户已启用的保障措施，或因 L2/L3 自动增加与实际目标无关的文档和流程
- 为形式完整机械执行 M09-M16，或用低成本检查证明其观察不到的行为

## 4. 输出要求

- 改动范围清楚
- 风险清楚
- 验证结果清楚
