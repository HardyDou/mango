# 供应商准入系统实施与验证计划

## 交付物

1. DEL-001 -> TD-001：交付 `supplier-api/core/starter/starter-remote`、邀请与申请 migration、定向测试；完成定义为邀请可单次消费且资料版本不可变。
2. DEL-002 -> TD-002：交付 workflow 适配、审核页面、字段权限、审计和集成测试；完成定义为并行审核与补正状态符合 SR-002。
- 规范：`rules/backend/01-code.md@1.4.0`、`rules/backend/08-test.md@1.4.0`；采用：模块实现和测试归属。
- 代码：`code-templates/business-module@commit:71cb8e4`；采用：复用模块骨架和检查入口。

## 实施任务

1. TASK-001 -> TD-001：从 `business-module` 基线生成四模块，新增邀请/申请实体、repository 和 migration；无前置；完成标准为架构检查通过且字典字段一致。
2. TASK-002 -> TD-001：实现邀请创建、摘要存储、条件消费和资料提交事务；前置 TASK-001；完成标准为并发请求只产生一个申请和任务。
3. TASK-003 -> TD-002：实现 workflow 端口、并行任务汇聚、补正重开和字段权限；前置 TASK-001；完成标准为状态图全部合法路径可执行、非法路径返回冲突错误。
4. TASK-004 -> TD-002：实现采购、法务、财务页面和供应商提交页；前置 TASK-002、TASK-003；完成标准为动作由服务端权限与状态驱动。

## 顺序与依赖

TASK-001 先稳定表和协议；TASK-002 与 TASK-003 可在其后并行；TASK-004 在提交和审核 API 稳定后开始。企业信息核验沙箱不可用只阻断外部核验用例，不允许跳过邀请、状态和权限验证。

## 数据与切换

先执行新增表 migration，再创建权限和菜单但默认不分配；在测试租户完成全流程后为试点采购角色授权。发现重复申请、状态越迁或银行字段越权可见时立即停止试点并关闭入口；不删除已审核记录。

## 验证与回滚

1. VAL-001 -> TASK-002：运行邀请并发与提交事务测试，使用同一令牌发起 20 个并发请求；断言一个成功、一个申请、一个采购任务，其余返回稳定冲突错误；报告存入任务证据目录，失败则停止 TASK-004。
2. VAL-002 -> SR-002：运行 workflow 集成测试和三角色浏览器用例；断言双通过准入、任一驳回补正、重复事件幂等，法务不可见银行账号；失败则关闭试点权限并保留审计。
- 回滚：撤销菜单和角色权限、关闭 workflow 事件订阅；代码回滚到引入模块前提交，新增表保留只读等待确认后处理。
- 剩余风险：企业信息核验服务的生产限流需在试点数据中继续观察。
